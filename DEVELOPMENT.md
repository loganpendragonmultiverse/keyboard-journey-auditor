# Development handoff

Approved scope: A local static demonstration plus an embeddable JavaScript recorder that a developer explicitly installs in a selected test root. Each session requires an owned-test-page and normal-window attestation. Anonymous element slots, safe tag/role categories, Tab direction, default-prevention evidence, elapsed time and sequence numbers support focus-order review and possible-trap evidence.

Idle by default; explicit start only. Never reads or exports text, input values, labels, names, IDs, page URLs, clipboard data, passwords or typed contents. Only Tab and Escape are interpreted; other keys are discarded. Password focus observed within the selected root, an observed Tab exit from that root, Escape, window blur, page hiding, page departure, event limit and timeout stop collection and remove listeners. Mouse or programmatic focus changes outside the root are not independently monitored; no outside-root events are recorded. Evidence stays in memory until a user reviews and exports it; clearing discards it. No telemetry, data uploads, persistent storage, permission prompts or continuous background collection. Serving the application loads its static assets; the recorder does not send captured evidence to a server.

No browser extension, cross-origin inspection, automatic site crawling, private browsing inspection, screen-reader audit, WCAG certification, shadow-root traversal or iframe traversal. Private mode cannot reliably be detected from a webpage: users must attest a normal window, and private browsing use is unsupported. Only instrument developer-owned synthetic test pages. The host page can already observe its own events; this library is not a security sandbox against a hostile host. Potential stationary focus and two-element cycles are heuristics; modal focus loops may be intentional and missed/false-positive traps are possible. Session limits: 500 events and five minutes. A pending Tab is sampled after 80 ms; slower dynamic focus updates may be missed.

Repository target: `loganpendragonmultiverse/keyboard-journey-auditor`. Candidate version: `v0.1.0`. Source must remain independent of all existing portfolio implementations. Shared community files and pinned CI conventions follow the canonical portfolio.

Run `npm test`, `npm run check`, `npm run build` and `npm audit --omit=dev`. Tests use Node built-ins; the distributable is static HTML/CSS/ES modules.

## Publication gate

This candidate does not authorize bypassing protected branches, failed checks or security review. Before a public release: review scope and source; run CI and CodeQL; configure protected main and required checks, squash-only merges, resolved conversations, read-only workflow permissions, security reporting, scanning and dependency alerts; obtain maintainer release review; build from the reviewed annotated tag; verify downloadable SHA-256 values; publish exact approved source/artifacts. Enable Pages for the keyboard app after browser acceptance. Parent task owns catalog coordination: update release register, catalog, generated information pages and sitemap only after verified GitHub release evidence, then render/deploy/live-verify and reconcile the Open Source Engine. Reconcile/audit organization all-activity watches. Do not advertise candidate versions as released.
